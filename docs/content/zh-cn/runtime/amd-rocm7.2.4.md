### 指定 FlagTree 版本

如需使用上述之外的 FlagTree 版本，给 `docker run` 传入 `-e FLAGTREE_VERSION=<版本>`，或容器运行中执行 `compiler flagtree <版本>`：该版本会在应用启动前安装到 `/opt/flagtree`，无需重建镜像。写全 `0.7.0+<后端>3.6` 可精确指定某个构建。

### 指定 FlagGems 版本

给 `docker run` 传入 `-e FLAGGEMS_VERSION=<版本>`，即可在应用启动前装上该 FlagGems 发布版，无需重建镜像。`-e FLAGGEMS_VERSION=latest` 取的是**每日线**上的最新构建（领先于下一个发布版）：它是「每日线最新」，不与镜像里已有的版本比较。wheel 约 13 MB，每个容器只取一次。容器内安装会保持其余依赖与构建时一致；请求装不上时容器直接起不来，而不是带着另一个 FlagGems 启动。

## 启动

**使用容器工具包** *(可选)*：

```bash
docker run --rm -it \
  --runtime amd \
  --device /dev/kfd \
  --device /dev/dri \
  harbor.baai.ac.cn/flagos-runtime/flagos-runtime-amd-rocm7.2.4:2.3.0 bash
```

**无需工具包** —— 直接使用 docker / podman：

```bash
docker run --rm -it \
  --device /dev/kfd \
  --device /dev/dri \
  --group-add video \
  --security-opt seccomp=unconfined \
  harbor.baai.ac.cn/flagos-runtime/flagos-runtime-amd-rocm7.2.4:2.3.0 bash
```

## 更新日志

### 2.3.0

*2026-10-31 13:13:04*

基于修正后的基础镜像重建：`HIP_VISIBLE_DEVICES=all` 这个 ENV 已移除，因此该镜像现在
开箱即可枚举全部 GPU，而不再枚举到 0 张卡。HIP 7.2 只接受设备序号或 GPU UUID，
而基础镜像此前设置的是 NVIDIA 习惯的 `all`，被解析成空设备列表：
`torch.cuda.device_count()` 返回 0，而 `rocm-smi` 却能列出全部卡。
包、编译器与版本均无变化 —— venv 和 flagcx 依赖与上一次推送完全相同。

*2026-10-31 09:25:08*

flagcx 0.14.1 成为该后端的运行时依赖：configs.yaml deps: 现在固定 flagcx==0.14.1+rocm7.2.4，
因此 DEPS 安装会从厂商索引拉取它，FlagTree 会把 libflagcx.so 解析到该包中的副本，
而不是 triton/_C 自带的那份。镜像其余内容不变。

*2026-10-27 10:04:40*

该镜像的基础镜像新增 hipsolver、hipfft 与 miopen-hip 开发包。torch 的头文件在 USE_ROCM
下会引入这些包，而 flagcx 的 torch wheel 在本镜像内针对它们编译，因此 wheel 构建成功需要这三个包。

*2026-10-27 06:29:51*

该后端 runtime 镜像的首次发布。它在基础镜像（ROCm 7.2.4，gfx1100）之上叠加了 ROCm torch 闭包
—— torch 2.11.0+rocm7.2、torchvision 0.26.0+rocm7.2、torchaudio 2.11.0+rocm7.2、
numpy 1.26.4 —— 以及 amd 后端随附的 ROCm triton 3.6.0，并加入 FlagTree 0.7.0+amd3.6
与 FlagGems 5.4.0。
